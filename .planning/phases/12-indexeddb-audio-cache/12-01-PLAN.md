    - After each `set()`, call `getSize()`. If total > MAX_CACHE_SIZE (50MB = 50 * 1024 * 1024), open a readwrite transaction, iterate all entries sorted by `lastAccessedAt` ascending, delete entries until total drops to 80% of MAX_CACHE_SIZE (40MB). Use `tx.store.openCursor()` iteration.

    DB singleton pattern:
    - `openDB<AudioCacheDB>('speaktts-cache', 1, { upgrade(db) { db.createObjectStore('audio-cache'); } })`
    - Cache the promise, reuse across calls.

    Cache key generation:
    - `computeCacheKey(text, voice, model, source)` — encodes `${source}:${model}:${voice}:${text}` with `TextEncoder`, hashes with `crypto.subtle.digest('SHA-256', ...)`, returns hex string.

    **Modify the `textToSpeech()` function body** — insert cache lookup BEFORE the primary proxy call, and cache write AFTER a successful proxy response:

    ```typescript
    export async function textToSpeech(
      text: string,
      voiceOverride?: string
    ): Promise<string> {
      const config = getRuntimeModelConfig();
      const source = config.ttsSource;
      const model = config.ttsModel;
      const voice = normalizeTtsVoice(source, model, voiceOverride || config.ttsVoice);

      // Cache-first: check IndexedDB before network call
      const audioCache = getAudioCache();
      try {
        const cached = await audioCache.get(text, voice, model, source);
        if (cached) {
          return await blobToBase64(cached);
        }
      } catch {
        // Cache read failed — proceed with network call
      }

      try {
        const base64 = await proxyTTS({ source, model, voice, text });
        // Store in cache (fire-and-forget, errors logged internally)
        const { base64ToBlob } = await import('../utils/audio');
        audioCache.set(text, voice, model, source, base64ToBlob(base64)).catch(() => {});
        return base64;
      } catch (primaryError) {
        // ... existing fallback logic remains unchanged
      }
    }
    ```

    Key integration details:
    - Cache check wraps in its own try/catch so a broken IndexedDB never blocks TTS.
    - Cache write is fire-and-forget: `.catch(() => {})` (the `set()` method itself logs warnings internally, so the catch here just prevents unhandled rejection).
    - Use dynamic `import('../utils/audio')` for `base64ToBlob` inside the success path to keep the import clean, OR add it to the top-level static imports alongside `blobToBase64`. Either approach is fine — prefer static import for consistency.
    - The fallback path (when primary TTS fails and fallback model is used) does NOT cache the fallback response — this avoids caching lower-quality audio.
    - `useTTS.ts` remains COMPLETELY UNTOUCHED — it still receives a base64 string from `textToSpeech()` and processes it the same way.
